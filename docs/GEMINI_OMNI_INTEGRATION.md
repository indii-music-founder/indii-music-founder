# Gemini Omni Flash integration

This repository uses the public-preview model `gemini-omni-flash-preview` through the Gemini Interactions API. The implementation follows Google's current [Omni guide](https://ai.google.dev/gemini-api/docs/omni) and uses `@google/genai` 2.x.

## Product surface

`OmniWorkflow.tsx` exposes the four documented task modes:

- `text_to_video`: prompt and optional timecoded storyboard.
- `image_to_video`: the first uploaded image is tagged as `<FIRST_FRAME>`; remaining images are references.
- `reference_to_video`: up to eight subject or style images are tagged `<IMAGE_REF_N>`.
- `edit`: edit one uploaded video, or continue a stored result through `previous_interaction_id`.

The renderer sends only validated gateway data. It never receives the Gemini API key and never uploads directly to Gemini.

## Creative pipeline handoffs

Generated assets remain durable `HistoryItem` records with canonical `gs://` URIs, so the creative stages can reuse media without downloading and re-uploading it manually:

- Veo video → Omni: opens as an uploaded-video `edit` input.
- Image → Omni: opens either as the `<FIRST_FRAME>` for `image_to_video` or as a subject/style reference for `reference_to_video`.
- Image → Veo: opens as a first frame, last frame, or reference image.
- Omni video → Veo: preserves the Omni video as the active source, extracts and persists its final frame, then uses that image as Veo's next first frame.
- Veo or Omni video → timeline editor: opens the original durable video directly as a timeline clip.
- Omni video → Image Studio: extracts and persists the final frame as an image input.

The Omni → Veo bridge intentionally uses frame continuity. Google's Veo extension API accepts only videos previously generated by Veo, while Omni explicitly does not support video extension. Passing an Omni MP4 as a Veo extension input would therefore be an invalid provider request.

### Reusable asset drag and drop

Gallery, Project Assets, Resources, Creative Clipboard, Veo Dailies, and the timeline library all publish the same versioned `application/x-indii-creative-asset+json` payload. The payload contains only safe asset metadata and durable URL/storage references—never media bytes, credentials, or API keys. Compatibility payloads remain available while older canvases migrate.

The primary drop destinations infer the safest useful role:

- Omni: video becomes an edit source; the first image becomes a starting frame; later images become references.
- Veo: images fill first frame, last frame, then references; video becomes a persisted final-frame continuity anchor; audio attaches to the shot.
- Timeline: image, video, and music assets become clips at the drop position.
- Infinite Canvas: image/video resources are reconstructed from the shared payload when the item is not already present in local history.

Documents and other project resources carry the same drag identity, but creative stages reject unsupported media types without moving, copying, or deleting the underlying resource.

## Server flow

1. Authenticate the Firebase callable request and parse `GenerateOmniRemixSchema`.
2. Validate that every Firebase Storage input uses the project bucket and the authenticated user's `creative/{uid}/…` namespace.
3. For uploaded-video edits, enforce the documented 10-second limit and a 256 MiB server intake cap, download to function temp storage, upload through Gemini Files, and poll until the file is `ACTIVE`.
4. Create one stored, synchronous Interactions request with the documented task, aspect ratio, 3–10 second duration, and URI delivery.
5. For stateful edits, verify that the previous job is completed, owned by the caller, and contains the matching provider interaction ID before forwarding it.
6. Poll incomplete interactions, retrieve inline or URI output, persist the MP4 in Firebase Storage, and record the provider interaction ID and usage metadata.
7. Settle the reserved cost after durable output; void it and remove partial output on failure.

Omni paid-tier Standard pricing is reserved at approximately $0.10 per generated second. The server recomputes the estimate and rejects mismatches.

## Deliberate limitations

The UI does not offer uploaded audio references, voice editing, video extension/interpolation, multi-video prompting, system instructions, sampling controls, or a negative-prompt field because the preview does not support them. Desired dialogue, music, ambience, exclusions, and timing belong in the regular prompt.

Google automatically applies invisible SynthID watermarking to all generated Omni videos. The app records this provider guarantee as `synthIdAppliedByProvider`; there is no user toggle.

Uploaded-video editing is region-restricted by Google. Deployments serving users in the EEA, Switzerland, or the United Kingdom must disable that intake based on reliable account/region policy; stateful editing of model-generated videos remains supported there.

Stored paid-tier interactions are retained by Google for 55 days by default. The app uses storage because stateful follow-up edits require the previous interaction; privacy and deletion policies should account for that provider retention window.

## Configuration

- Required secret: `GEMINI_API_KEY` from a paid-tier Gemini Developer API project.
- Default model: `FUNCTION_INTELLIGENCE_MODELS.VIDEO.OMNI`.
- Optional rollout override: `GEMINI_OMNI_FLASH_MODEL`.
- Optional polling controls: `VIDEO_POLL_INTERVAL_MS` and `VIDEO_MAX_POLLS`.

Set the production secret with Firebase Secret Manager; never use a `VITE_` environment variable for this credential.
