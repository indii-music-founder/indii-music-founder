## Prepared change and remaining acceptance

The new `executionGraph.ts` contract separates node kinds, validates lineage
and dependencies, and rejects completion based on model assertions, absent
acceptance criteria, failed evidence or a different artifact identity.
`executionGraphStore.ts` supplies transactionally persisted operational graphs,
idempotent intake receipts, exact-identity intelligence matching and server-only
Firestore event adapters. The existing bug function persists the durable
GitHub pointer only after its current intake path finishes. Graphs retain issue
pointers; they do not create/close issues or copy bug descriptions into a
second tracker. Client access remains denied by existing default-deny rules.

This is a foundation for phases 1–3, not completion of phases 0–16. Before
completion: validate real persistence and deployed triggers; wire the daily
brief producer and all GitHub/CI/CodeRabbit/Sentry event sources; test genuine
report intake and exact-event replay; finish Blender convergence; then proceed
through bounded execution and the business programs. No self-repair or
self-upgrade end-to-end path has yet been demonstrated.
