## 17. Product-development loop

A defining current operating pattern is:

**use the product → discover a bug/limitation/missing connection → capture the evidence → classify the issue → hand it to the appropriate coding/agent workflow → implement/connect → test/CI/review → retest inside indii**

This means current founder work is often less about inventing disconnected new screens and more about:

- wiring already-designed surfaces to real services;
- adding bounded tools when a specialist needs a missing capability;
- converting live-use limitations into explicit engineering work;
- improving truthfulness and observability when the system cannot complete a task.

---

## 18. How to use this inventory

For funding or diligence:

1. start with the user's actual question;
2. select only the relevant surfaces;
3. verify current implementation/live status;
4. distinguish repository presence from production proof;
5. avoid turning breadth into an unsupported “everything is finished” claim.

The product's breadth is an asset. Truthful capability state is more important than claiming every surface is complete.
