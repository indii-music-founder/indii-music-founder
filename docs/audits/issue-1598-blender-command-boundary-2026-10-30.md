# ISSUE-1598: Blender command boundary — 2026-10-30

Status: PARTIAL; implementation awaiting final gates and installed-app acceptance.

The live addon previously accepted unauthenticated JSON and executed arbitrary Python. The runner also executed arbitrary customScriptPath contents. The repair removes these execution paths and permits only ping, scene inspection and bounded integer frame selection. Unknown/custom render configuration is rejected before scene or filesystem mutation; five fixed procedural templates remain supported. IPC, MCP and agent declarations now describe the restricted commands.

Each addon instance generates a random 32-byte pairing credential, invalidated on stop or bind failure. The owner explicitly copies it from Blender's sidebar into the desktop Blender panel. Sender-validated IPC passes it to private main-process memory and the local MCP child environment, never agent arguments or persistent settings. The input clears after submission. Stopping through the addon clears the clipboard only if it still contains that session code. A clipboard manager may retain copied values; this flow does not claim to control external clipboard history. Pairing reconnects the local child and refuses active local operations or tracked renders; failed setup and disconnect clear its stored credential.

The addon binds IPv4 loopback synchronously before announcing success. It accepts at most eight simultaneous connections, one newline-delimited command up to 64 KiB, and a ten-second total read deadline. A fixed-length credential is compared using hmac.compare_digest. Requests fail before queueing when authentication/schema/framing is invalid. A bounded main-thread queue handles all bpy access. Expired or cancelled pending commands cannot execute later; stopped instances do not resume on a new instance's global running flag. Client responses require explicit ok/error status; malformed responses and failed commands cannot be reported as successful tool execution.

Seven Python checks cover pure schemas, native sockets (missing/wrong credential, forbidden Python, oversize and incomplete frames), authenticated queue admission with expiration, and a real bind conflict. They provide no bpy module and do not claim actual scene execution. Four runner config checks cover executable/unknown config and validation ordering. Thirty existing affected tests passed as structural-only evidence, and the final seven-test tool suite passed after outcome-honesty changes. Initial typechecks and scoped lint passed; the full required pre-commit gate passed, including workspace typecheck, staged lint, capability/workflow checks, API boundaries, function invariants, ledger integrity and affected tests. The isolated local/harness MCP package verification passed. Vitest now invokes both Python security scripts so normal suite runs include these contracts. No authentication/customer/provider mocks were added for these claims.

Remaining acceptance: install the updated addon and desktop build, pair through their real UI, verify ping and scene read, set a real scene frame and observe it, restart and prove old pairing rejection/new pairing, exercise bind errors and stop during pending work, and run a genuine procedural render. No deployment, external transmission, customer state mutation, installed-Blender proof or issue closure is asserted. File-read scopes are delivered separately; all remaining ISSUE-1598 acceptance must be reconciled before closure.
